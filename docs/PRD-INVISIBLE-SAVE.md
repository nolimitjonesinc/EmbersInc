# PRD: Invisible Save & Backup System

**Created:** 2026-03-31
**Status:** Draft
**Sprint:** Next (after current stabilization)
**Depends on:** Existing auth, Supabase, local autosave infrastructure

---

## 1. Overview

Replace the current "save locally, hope they sign up later" model with a system where saving and backup are fully automatic. The user never makes a storage decision. Two enrollment paths: **Family-Started** (preferred) and **Solo-Started** (fallback).

---

## 2. User Flows

### Mode A: Family-Started (Primary Path)

This is the default. The buyer (adult child) sets everything up. The elder just talks.

**Family Member Flow:**
1. Family member visits embersinc.org
2. Taps "Set Up Embers for Someone You Love"
3. Enters their own email — receives magic link — authenticated
4. Creates a "family circle" — enters the elder's name ("What should we call them?")
5. Gets a unique invite link (and optional QR code)
6. Sends link to elder via text, email, or prints QR code
7. Dashboard shows: elder's stories, backup status, activity

**Elder's Flow:**
1. Elder receives link from family member (text or printed QR)
2. Taps link — opens Embers in browser
3. Sees: "Hi Margaret, [family member] set this up for you. Ready to share a memory?"
4. Taps the flame — starts talking
5. Everything autosaves locally AND to cloud (account already exists)
6. Elder never sees a login screen, signup form, or storage decision

**Key Details:**
- The invite link creates a pre-authenticated session (magic link baked in)
- Link expires after 7 days but can be regenerated by family member
- Family member can add multiple elders to their circle
- Elder's browser gets a long-lived session token (30 days, auto-refresh)
- If session expires, elder taps the same link again (or family sends a new one)

---

### Mode B: Solo-Started (Fallback)

For elders who find Embers on their own, or when no family member is involved.

**Flow:**
1. User visits embersinc.org
2. Taps "Share a Memory"
3. Brief onboarding: "What should I call you?" (voice or type)
4. Conversation begins immediately — no signup
5. Local autosave starts immediately (every 5 seconds during active conversation)
6. After first meaningful exchange (30-60 seconds, or first natural pause):
   - Embers says via TTS: "This is a wonderful story, [name]. I'd love to keep it safe for you. What's your phone number?"
   - User says phone number out loud
   - Embers repeats it back: "I heard 555-867-5309 — is that right?"
   - User confirms ("yes" / "that's right")
   - Embers sends SMS with 6-digit code
   - Screen shows large-font code entry (or family member enters it)
   - Embers: "You're backed up now. Everything you share with me is safe."
7. From this point: all local stories migrate to cloud, future saves go to both
8. If user declines or ignores: local autosave continues, gentle re-prompt at end of session

**Key Details:**
- Phone number is the primary identity method (voice-friendly, elderly-familiar)
- Email is secondary fallback (typed, not voice — email addresses are hard to say)
- If user says "I don't have a phone number," offer email typed by helper
- SMS code is 6 digits, large font, 10-minute expiry
- One re-prompt at session end if they didn't enroll: "Before you go — want me to keep this safe?"
- Never more than 2 prompts per session (not naggy)

## 3. Autosave Behavior

### Local Autosave (Always On)
- Saves conversation state to localStorage every 5 seconds during active conversation
- Saves on: pause in speech, AI response received, browser blur/visibility change
- Format: full conversation transcript + metadata (persona, chapter, timestamp)
- Keeps last 3 conversations in local storage (older ones evicted if not cloud-backed)
- On return visit: "Welcome back, [name]. Would you like to continue where you left off?"

### Cloud Backup (After Enrollment)
- Triggered automatically after identity is established
- First action: migrate all local conversations to Supabase
- Ongoing: every local save also writes to Supabase (debounced, 10-second minimum)
- Conflict resolution: most recent timestamp wins (same as current dualStorage)
- Offline handling: queues writes, syncs when connection returns
- Status indicator: subtle icon (not text) showing backup status
  - Green ember glow = backed up
  - Amber pulse = syncing
  - No indicator = local only (pre-enrollment)

## 4. Save Language Rules

| State | What User Hears/Sees | What It Means |
|-------|---------------------|---------------|
| Local only, active conversation | Nothing (silent autosave) | Saving to browser |
| Local only, session ending | "This memory is protected on this device" | localStorage only |
| Cloud enrolled, saving | Nothing (silent) | Writing to both |
| Cloud enrolled, session ending | "Safe and backed up" | In Supabase |
| Cloud enrolled, offline | "I'll back this up when you're online again" | Queued for sync |
| Enrollment prompt | "I'd love to keep this safe for you" | Prompting for identity |

**Rules:**
- Never use the word "saved" for local-only state
- "Protected" = local only (honest but not alarming)
- "Safe" or "backed up" = cloud confirmed
- Never mention "cloud," "server," "database," or "browser storage" to the user

## 5. Family Circle Dashboard

The family member who sets up the account gets a simple dashboard:

**What they see:**
- List of elders in their circle
- Each elder: name, last activity, story count, backup status
- "Send New Link" button (regenerate invite)
- "Suggest a Prompt" button (sends a conversation starter to the elder)
- Story feed: recent stories from their elders (if sharing is enabled)

**What they don't see:**
- Technical details about storage or sync
- Raw conversation transcripts (only finished stories)
- Admin controls beyond basic circle management

**Access:**
- Family member logs in with their own magic link
- Dashboard is at embersinc.org/family (or /dashboard)
- Mobile-responsive but not mobile-first (family members are younger, can handle desktop)

## 6. Session & Identity Management

### Pre-Enrollment (Solo Mode)
- Anonymous session with localStorage persistence
- Session identified by browser fingerprint + localStorage key
- No cross-device capability
- Gentle enrollment prompts (max 2 per session)

### Post-Enrollment
- Phone number or email is the identity anchor
- Long-lived session token (30 days, auto-refresh on activity)
- Cross-device: elder can open Embers on any device, enter phone → magic link → all stories there
- Family-started sessions: token is embedded in the invite link

### Session Recovery
- If session expires: show "Welcome back, [name]" + one-tap re-auth (SMS or magic link)
- If cookies cleared: same flow — phone number → code → back in
- Family can trigger re-auth link from their dashboard
- Voice-guided: "It looks like we need to reconnect. Can you tell me your phone number?"

## 7. Edge Cases

| Scenario | Behavior |
|----------|----------|
| Elder talks for 20 min, never enrolls, closes browser | Local data preserved. On return, prompted to continue + enroll |
| Elder enrolls, then clears cookies | Stories safe in cloud. Re-auth via phone/magic link |
| Two family members set up same elder | Merge prompt on family dashboard. Elder's stories stay intact |
| Elder has no phone or email | Family-started mode only. Family member manages everything |
| Internet drops mid-conversation | Local autosave continues. Cloud sync resumes when online |
| Elder uses different device | Post-enrollment: phone → code → all stories sync. Pre-enrollment: stories stuck on original device |
| Family member removes elder from circle | Elder's stories are NOT deleted. Elder becomes a solo user with cloud backup intact |
| Local storage full | Evict oldest non-backed-up conversations with warning. Prioritize enrollment prompt |

## 8. What Changes from Current System

| Current | New |
|---------|-----|
| Auth gate appears after 1st story | Enrollment happens during conversation, by voice |
| "Saved" means localStorage | "Protected" (local) vs "Safe" (cloud) — honest language |
| Guest users have no path to cloud backup during conversation | Solo users prompted at natural pause |
| Family features are post-signup | Family setup IS the signup (Mode A) |
| Login page with email form | Voice-captured phone number or family-sent link |
| No cross-device for guests | Cross-device after enrollment (phone-based identity) |

## 9. What Does NOT Change

- Supabase as the cloud backend
- Stripe subscription tiers and pricing
- Conversation AI (GPT-4o, personas, memory system)
- Voice recognition and TTS
- Life Book chapters and story classification
- Local autosave infrastructure (enhanced, not replaced)

---

## 10. Technical Notes (For Implementation)

- Phone-based auth: Supabase supports phone auth with OTP — use this
- Invite links: signed JWT with elder's pre-created user ID, family circle ID, expiry
- Session tokens: Supabase session with custom refresh logic (30-day window)
- Local-to-cloud migration: existing `migrateLocalStories.ts` can be adapted
- Save language: new utility function that returns the right string based on auth + sync state
- Family dashboard: new Next.js route, authenticated, reads from family_circles + embers_stories tables
- New Supabase tables needed: `family_circles`, `family_circle_members`
